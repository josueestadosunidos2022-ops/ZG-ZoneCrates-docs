## Guía detallada de esta entrega

ZONE CRATES 2.1.0-beta2 — COFRES FÍSICOS, COMANDOS Y CONFIGURACIÓN

Minecraft Forge 1.20.1 · Java 17 · protocolo 4
Un único JAR universal: zonecrates-2.1.0-beta2-protected.jar.
Usar exactamente esta versión en cliente y servidor. Reemplazar el JAR anterior;
no mantener dos versiones. ZoneCore 2.x es obligatorio en servidor, opcional en
cliente. Laboratorio: Core 2.1.5, servidor Forge 47.4.10 y cliente Forge 47.4.0.
No mezclar beta1/protocolo 3 ni 2.0.6/protocolo 2 con esta beta2.

CAMBIOS
Siete cofres colocables propios, con tapa arqueada articulada, asas, patas,
herrajes y gema. Progresión visual de Easy a Infinity en azul, violeta y cian.
Se conserva el rework anime medieval del catálogo, editor y ruleta de beta1.

Solo dos entradas de comando:
  /crates        catálogo, compra de llaves y apertura
  /crates editar editor y herramientas administrativas
Retirados: /zonecreate, /zonascreate y /zonecrates.
Permisos: zonecrates.open para jugadores; zonecrates.admin u OP nivel 2 para
edición, herramientas y protecciones administrativas. Integración Forge
PermissionAPI y ZoneRanks opcional.

CÓMO COLOCAR Y USAR LOS COFRES
Abrir /crates editar, seleccionar el nivel y pulsar Herramientas. Indicar nombre
exacto de un jugador conectado y pulsar Dar 1 cofre físico. También están en la
pestaña creativa Zone Crates. Las otras herramientas entregan llaves virtuales
del nivel y GodieCoins con cantidad decimal usando punto, por ejemplo 10.50.
Máximo por operación: 1000000.00 GC o 1000000 llaves; el saldo sigue sujeto a
los límites de la billetera existente. Las herramientas validan en servidor.

Interactuar con mano libre abre el catálogo del nivel de ese bloque. Se puede
comprar/usar una llave virtual o abrir directamente llevando una llave física
del nivel correcto. La llave de otro nivel se rechaza. Por defecto los jugadores
pueden usar sus llaves físicas; en creativo no se consumen llaves físicas.
La tapa se abre con el evento del servidor y se cierra al terminar la duración.
Las llaves virtuales sí se consumen también en creativo.

IDs nuevos bajo zonecrates:
zone_easy_crate, zone_medium_crate, zone_hard_crate, zone_escarlata_crate,
zone_iluminaria_crate, zone_critical_crate y zone_infinity_crate.
El ID histórico zonecrates:crate se conserva como Easy. Los bloques viejos sin
propiedad tier adoptan Easy. No contienen un inventario de almacenamiento.
Las tablas de premios son globales por nivel, compartidas por todos sus bloques.

CONFIGURACIÓN REAL DEL SERVIDOR
Carpeta: config/ZONEMODS/zonecrates/
  ajustes.toml  reglas generales y efectos
  cajas.toml    precios, habilitación, esperas, pesos y objetos por nivel
Se generan al arrancar. La primera generación de cajas.toml parte de los premios
ya guardados en ese mundo. No sobrescribirlo con el ejemplo de esta entrega.
Después, el editor guarda en TOML y en SavedData; los cambios externos requieren
Recargar TOML desde /crates editar > Herramientas. Un error rechaza la recarga
completa y conserva las reglas activas. El editor rechaza sobrescribir un archivo
modificado externamente sin recargar. Cada instalación tiene un catálogo: no
compartir la misma carpeta de configuración entre mundos con tablas distintas.

ajustes.toml — 26 controles activos, valores por defecto y alcance:
general.enabled = true             habilita compra/apertura
general.keyShopEnabled = true      tienda de llaves virtuales
general.menuOpeningEnabled = true  apertura desde /crates; el bloque sigue usable
general.requireNearbyCrate = false exige cofre del mismo nivel para abrir por menú
general.interactionRadius = 6      radio de proximidad, 1–8 bloques
general.maxRewardsPerTier = 10     límite de NUEVAS altas, 1–10; no borra premios
general.maxAddedStackCount = 64    limita nuevas copias desde la mano, 1–64
keys.physicalKeysEnabled = true    acepta llaves físicas
keys.physicalKeysAdminOnly = false restringe dichas llaves a administradores
death.keepWallet = true            conserva saldo al morir
death.keepKeys = true              conserva llaves virtuales al morir
physical.adminOnlyPlacement = true colocación solo administrativa
physical.adminOnlyBreaking = true  retirada solo administrativa
physical.explosionProof = true     protege cofres frente a explosiones
opening.durationTicks = 100        animación de 20–200 ticks (20 = 1 segundo)
opening.minimumIntervalTicks = 20  intervalo mínimo adicional, 0–1200 ticks
opening.allowSkip = true           permite revelar el resultado antes
opening.fullInventoryMode = "DROP_REMAINDER"
  DROP_REMAINDER inserta lo posible y suelta únicamente el sobrante.
  REQUIRE_SPACE comprueba el premio elegido; si no cabe no consume llave/espera.
effects.soundEnabled = true        sonido de interfaz/ruleta
effects.soundVolume = 0.5          volumen, 0–1
effects.particlesEnabled = true    partículas de los cofres físicos
effects.particleInterval = 8       probabilidad por animateTick, 2–200; menor = más
effects.idleMotion = true          movimiento ambiental de cristales
effects.floatingLabels = true      muestra nivel sobre el cofre
effects.labelDistance = 16         distancia de etiquetas, 4–32 bloques
logging.auditActions = true        registra compras, aperturas y herramientas

El bloqueo común entre aperturas usa el mayor de duración e intervalo mínimo.
Se aplica además cooldown_seconds del nivel. Saltar la animación no salta ese
bloqueo. Los efectos del servidor prevalecen sobre los toggles locales de Ayuda.
La protección de explosiones no sustituye un mod de regiones frente a todos los
tipos de edición que otros mods puedan implementar.

cajas.toml tiene siete secciones: tiers.easy, medium, hard, escarlata, iluminaria,
critical e infinity. Cada una admite:
  enabled = true
  key_price = "10.50"        texto decimal exacto, positivo, máximo dos decimales
  cooldown_seconds = 0       0–86400
  default_weight = 100       1–1000000; peso inicial de nuevas altas
  rewards = []              si la tabla está vacía
O entradas [[tiers.easy.rewards]] con item, count 1–64, weight 1–1000000 y nbt.
nbt es SNBT de la etiqueta del objeto, no del ItemStack completo. forge_caps es
SNBT opcional de ForgeCaps; se exporta para conservar capacidades de objetos.
No cambiar esos datos sin conocer el mod de origen. El editor copia desde la
mano nombres, encantamientos y datos del objeto. Máximo técnico: diez premios.
La probabilidad es peso / suma de pesos: 100 y 300 dan 25% y 75%.
Los premios de las capturas son de laboratorio y no se instalan como tabla real.
